🚨 结论：INSERT 实际防线在 MySQL 层，应用层存在审计缺口

实际生效的拦截来自 mysql.py:77 中 SET SESSION TRANSACTION READ ONLY， 这是会话级别的 MySQL 写保护，任何写操作都会触发 ERROR 1792。

但这属于"偶然防御"，不是设计意图：

  • ReadOnlyCheck 已在后续重构中移除（功能合并至 SQLAuditCheck 的 _ADMIN_ONLY_STATEMENTS，新增了 INSERT/MERGE）
  • INSERT 安全通过所有应用层检查，白白消耗了两次 LLM 推理 + 一次 MySQL 连接
  • 如果未来支持开启读写事务的适配器（如 PostgreSQL 未设置 READ ONLY），INSERT 将直接被写入数据库
  • 应该在 sql_auditor.py 的 _ADMIN_ONLY_STATEMENTS 中加入 INSERT/MERGE，在应用层就拦截
