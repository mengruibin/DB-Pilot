## 运维交互安全原则

> 依据 PRD §8（安全设计）及 §5.3（故障自动排查），数据库运维场景中的误操作代价极高。前端必须作为最后一道防线。

### 危险操作确认机制（依据 PRD §8.1 Layer 3）

- [ ] MUST 所有在语义上会修改数据或表结构的操作，在执行前弹出二次确认对话框
- [ ] MUST 二次确认对话框必须包含以下三要素（依据 PRD §8.1 Layer 3 要求"说明影响范围"）：
  - 即将执行的 SQL 语句全文（语法高亮渲染）
  - 预估影响行数（若后端无法提供，显示"影响范围未知——请人工评估"）
  - 明确的「取消」和「确认执行」按钮，确认按钮 MUST 使用危险色（红/橙）并附带 1.5 秒悬停冷却期
- [ ] MUST NOT 提供"不再提示"或"跳过确认"类复选框——每次写操作必须单独确认
- [ ] MUST Agent 生成的诊断建议中包含 `KILL`、`DROP`、`ALTER`、`TRUNCATE` 等操作时，前端 MUST 将其渲染为需确认的按钮而非可自动执行的代码块（依据 PRD §5.3 示例："必要时 KILL 82491"）
- [ ] SHOULD 巡检报告中建议的 `CREATE INDEX`、`OPTIMIZE TABLE` 等改表操作，以"建议卡片"形式展示，附带「执行此建议」按钮，点击后走写操作确认流程

### 执行结果反馈范式

- [ ] MUST 每次 SQL 执行后展示三类反馈：执行状态（成功/失败/超时）、耗时（毫秒）、影响/返回行数
- [ ] MUST 执行超时（> 30s，依据 PRD §8.1 Layer 4）时展示明确超时提示 + 「终止查询」按钮
- [ ] MUST 执行失败时区分两类错误展示（依据 PRD §10.2"错误信息友好可读"）：
  - 用户可自行修正的错误（语法错误、表名拼写错误）→ 高亮错误位置 + 修正建议
  - 系统/权限错误（连接断开、权限不足）→ 展示原因 + 建议联系 DBA
- [ ] MUST NOT 在失败时将原始异常堆栈直接展示给用户（依据 PRD §10.2）

### 长任务进度与取消

- [ ] MUST 凡后端 Agent 工作流超过 3 步（如故障排查：检查连接→检查锁→分析锁等待链→结论），前端 MUST 以步骤列表形式展示当前进度，已完成步骤标记 ✅，进行中步骤显示加载动画
- [ ] MUST 巡检报告生成（20+ 检查项，依据 PRD §5.4）逐项实时更新进度条，已检查项数/总项数实时可见
- [ ] MUST 所有超过 5s 的操作提供「取消」按钮，取消后 MUST 回退到操作前状态（前端不保留部分结果）
- [ ] MUST SSE 流式连接中断时（网络波动/服务端主动关闭），前端 MUST 保留已接收内容并在断开位置标记"连接中断"，同时展示「重新连接」按钮

### 会话超时与空闲策略（依据 PRD §8.2）

- [ ] MUST 用户无操作 30 分钟后，前端 MUST 自动断开 SSE 连接并清除内存中的目标数据库连接凭据（依据 PRD §8.2"会话超时自动清理"）
- [ ] MUST 即将超时前 2 分钟展示非阻断式倒计时通知，用户任一操作（鼠标移动除外）重置计时器
- [ ] MUST 超时发生后，用户发送下一条消息时 MUST 重新测试数据库连接有效性

## 敏感数据展示规范

> 依据 PRD §8.2（连接凭据安全）及 §8.3（权限模型），前端是敏感信息的最终展示边界。

### 查询结果脱敏规则

- [ ] MUST 查询结果表格中，匹配以下模式的列默认以 `***` 掩码展示（依据 PRD §8.2 凭据保护原则 + DBA 运维惯例）：
  - 列名包含 `password`、`passwd`、`pwd`、`secret`、`token`、`api_key`（大小写不敏感）
  - 列名包含 `phone`、`mobile`、`email`、`id_card`、`ssn`（PII 字段）
- [ ] MUST 每行掩码数据旁提供 👁 图标，点击后单行临时显示明文，5 秒后自动恢复掩码
- [ ] MUST NOT 提供"全部显示明文"一键操作

### SQL 日志与调试信息掩码

- [ ] MUST 前端对话历史中展示的 SQL 语句，若包含字符串字面量疑似凭据（如 `IDENTIFIED BY 'xxx'`），MUST 将凭据部分替换为 `'***'` 后展示
- [ ] MUST 前端开发者控制台中 MUST NOT 输出任何包含数据库连接信息（host/port/user/password）的日志
- [ ] SHOULD 生产构建中移除所有 `console.log` / `console.debug` 调用（<!-- TODO: 需人工确认 —— 选择方案 A: esbuild drop 配置, B: 自定义 Vite 插件, C: 代码规范禁止 + lint 检查 -->）

### 复制与导出限制

- [ ] MUST 查询结果中，用户选中含掩码列的单元格并按 Ctrl+C 时，剪贴板中该列内容 MUST 仍为 `***`（需显式点击 👁 后才可复制明文）
- [ ] MUST 结果导出（CSV/Excel）时，敏感列 MUST 默认不包含在导出范围内；用户手动勾选后在导出文件表头追加 `[包含敏感字段]` 标记
- [ ] SHOULD 导出文件附带生成时间 + 导出人标识水印，格式为 `Generated by DB-Pilot | 2026-06-30 15:30:00 UTC | User: xxx`（<!-- TODO: 需人工确认：PRD 未定义用户身份体系，"xxx" 需确认是 IP/浏览器指纹/登录账号 -->）

### 连接凭据展示

- [ ] MUST 连接管理页面中，已保存连接的密码字段永远以 `••••••••` 展示，无查看明文功能
- [ ] MUST 连接编辑表单中，密码输入框类型为 `password`，浏览器不自动填充
- [ ] MUST 连接测试时，若失败，错误信息中 MUST NOT 包含密码原文（即使后端返回了也要在前端过滤——依据 PRD §8.2"连接密码不在日志中输出"）

## 实时状态感知设计

> 依据 PRD §4.1 架构（SSE 实时推送）、§5.3（故障排查步骤展示）、§10.2（可用性要求），DBA 需要毫秒级感知数据库连接与执行状态。

### 连接状态指示（依据 PRD §10.2"连接测试提供明确的成功/失败反馈"）

- [ ] MUST 全局固定位置（顶部栏或侧边栏底部）展示当前目标数据库连接状态指示器，三态：
  - 🟢 已连接：显示数据库类型图标 + 实例标识（host:port/database），悬停显示连接建立时间
  - 🟡 连接中：显示旋转动画 + "正在连接..."
  - 🔴 已断开：显示断开原因 + 一键重连按钮
- [ ] MUST 连接状态变化后 1 秒内 UI 完成状态切换（依据验收标准"连接断开 1s 可见反馈"）
- [ ] MUST 连接意外断开（非用户主动操作）时弹出非阻断式 Toast 通知，持续 5 秒后自动收起

### 执行耗时可视化（依据 PRD §10.1 性能指标）

- [ ] MUST 每条 SQL/Agent 操作完成后，在结果卡片旁显示壁钟耗时
- [ ] MUST 耗时超过以下阈值时进行视觉标记：
  - < 500ms：无特殊标记（正常，依据 PRD §10.1"SQL 查询响应简单 < 500ms"）
  - 500ms – 2s：黄色标记 "⚠ 偏慢"（依据 PRD §10.1"SSE 首 Token < 2s" 的边界）
  - > 2s：红色标记 "🐢 慢" + 可点击查看执行计划入口
  - <!-- TODO: 需人工确认：慢查询阈值是否与目标数据库 `long_query_time` 配置联动 --> 
- [ ] MUST Agent 思考阶段（从发送消息到收到第一个有效结果）展示 ThinkingIndicator 动画 + 实时耗时计数器（毫秒递增）

### 错误分级提示（依据 PRD §10.2"错误信息友好可读"）

- [ ] MUST 错误消息按三级展示：
  - ℹ️ **提示**（Info）：非阻塞信息，如"索引建议已生成"、"巡检完成 20/20"
  - ⚠️ **警告**（Warning）：用户可自行处理的问题，如"您的查询耗时 3.2s，建议优化"、"连接空闲已 25 分钟，即将超时"
  - 🛑 **错误**（Error）：需系统或 DBA 介入，如"连接被拒绝：权限不足"、"死锁检测：事务 #82491 阻塞了 2 个查询"
- [ ] MUST 错误卡片区分"用户误操作"（提供修正指引）和"系统故障"（提供排查步骤 + 联系入口）
- [ ] MUST NOT 使用 alert() 弹窗展示任何错误——所有错误 MUST 以内联卡片或 Toast 形式展示且不阻断用户其他操作

### SSE 流式进度指示（依据 PRD §4.2 Agent 工作流 6 步）

- [ ] MUST 解析 SSE `type: "tool_call"` 事件，实时展示 Agent 当前调用的工具名 + 简要描述（如"正在查询慢查询日志..."）。**注意：工具调用步数动态变化（1~10步），前端需自适应展示，不可硬编码固定步骤数量。**
- [ ] MUST 解析 SSE `type: "thinking"` 事件，在可折叠区域内展示 Agent 推理过程（默认折叠，用户可展开，依据 PRD §4.2 多步推理需可见但不阻塞界面）。**2026-07-02 更新：`thinking` 内容从静态文本变为 LLM 流式推理输出（逐 token），建议以打字机效果或可折叠区域展示。可选字段 `agent_run_id`、`iteration`、`reasoning_type` 可用于调试面板。**
- [ ] SHOULD 故障排查模式下，每个排查步骤完成后前端播放轻微的完成音效 + 触觉反馈（若设备支持）以让 DBA 在后台窗口感知进度

## 命令输入与编辑约束

> 依据 PRD §5.1（NL2SQL 流程）、§9 Phase 2（SqlBlock + ResultTable），输入区需同时承载自然语言和 SQL 两种输入模态。

### 输入区行为规范

- [ ] MUST 输入区支持两种模式切换：「自然语言」和「SQL 编辑器」，默认为自然语言（依据 PRD §3.2 P0 优先级）
- [ ] MUST 切换到 SQL 编辑器模式时，展示 Monaco Editor（或等效代码编辑器）——含 SQL 语法高亮、括号匹配、缩进引导
- [ ] MUST NOT 在 SQL 编辑器模式下提供"自动执行"功能——用户 MUST 显式点击「执行」按钮或按 Ctrl+Enter（依据 PRD §8.1 Layer 3 设计精神：所有操作需用户确认）
- [ ] MUST 按 Shift+Enter 换行，Ctrl+Enter 提交执行
- [ ] MUST SQL 编辑器中粘贴多行 SQL 时（> 1 行），前端 MUST 弹出确认："检测到 N 条 SQL 语句，确认全部执行？"（依据 PRD §8.1 Layer 2：多语句检测）
- [ ] MUST 输入区底部显示当前连接的目标数据库标识（如 `mysql://prod-cluster:3306/orders`），防止用户在错误库上执行操作

### 历史命令管理（依据 PRD §10.2"所有操作可撤销或需二次确认"）

- [ ] MUST 自然语言和 SQL 输入历史均保留，存储到浏览器 localStorage
- [ ] MUST 历史记录限制最多保留 100 条，超出后 FIFO 淘汰
- [ ] MUST 历史记录使用 AES-256-GCM 加密存储，解密密钥从当前浏览器会话派生（浏览器关闭后历史不可读）——依据 PRD §8.2 凭据 localStorage 存储的安全原则外推至命令历史
- <!-- TODO: 需人工确认：是否需要服务端持久化历史以便跨设备同步？PRD 未提及，默认仅本地存储 -->
- [ ] MUST 历史面板支持搜索过滤（关键词匹配），不支持按时间范围查询
- [ ] MUST NOT 在历史列表中展示完整的 SQL 查询结果数据——仅展示输入文本 + 执行时间戳 + 状态（成功/失败）
- [ ] SHOULD 提供「清空历史」按钮，点击后二次确认后清除

### 语法辅助边界

- [ ] MUST SQL 编辑器中的自动补全基于目标数据库的 Schema 元数据（表名、列名），不基于历史查询结果数据（依据验收标准"补全仅基于元数据不缓存结果"）
- [ ] MUST 元数据补全来源：后端 `/api/connections/{id}/metadata` 返回的表/列/索引信息，前端缓存有效期 5 分钟
- [ ] MUST NOT 在自动补全列表中包含以下内容：
  - 历史 SQL 查询中出现的实际数据值
  - 其他用户/会话的查询历史
  - 目标数据库中未在元数据中声明的隐藏列
- [ ] SHOULD SQL 编辑器对以下危险关键字进行红色波浪线标注：`DROP`、`DELETE`、`TRUNCATE`、`ALTER`、`UPDATE`（不含 `SELECT ... FOR UPDATE` 中的 `UPDATE` —— 但 `FOR UPDATE` 同样需标记）—— 视觉警告不等于自动阻止，最终由后端 sql_auditor 裁定（依据 PRD §8.1 Layer 2）

### 键盘快捷键规范

- [ ] MUST 全局快捷键不拦截浏览器原生快捷键（Ctrl+T 新标签页、Ctrl+W 关闭标签页、F5 刷新）
- [ ] MUST 提供以下快捷键映射（<!-- TODO: 需人工确认：PRD Phase 5 提及键盘快捷键但未列举具体映射，以下为推荐默认 -->）：

  - `Ctrl+K`：打开命令面板（连接切换/历史记录/新建会话）
  - `Ctrl+L`：清空当前对话
  - `Escape`：终止正在执行的 Agent 操作 + 关闭 SSE 连接
